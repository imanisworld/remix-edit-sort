# Removed raw inventories — sanitized index

These files were generated by `scripts/inventory_library.py` and
`scripts/scan_library.py` during the 2026-08-15 cleanup. Each was a complete
listing of a real music library folder: **absolute local paths**, the whole
machine-specific directory structure, and per-track private metadata for every
file in it.

They totalled **143 MB across 234 files** in the committed tree, and
they are the single largest source of private library detail in this
repository. They have been removed from HEAD as part of the 2026-08-16
repo-hardening pass.

## Why removing them loses no audit evidence

An inventory is a *snapshot of what was there*, not a record of what a run
*did*. Everything needed to understand and reverse prior work is still
committed and untouched:

- the **plans** (`*-plan.json`, `plan*.json`) — exactly what each run proposed;
- the **undo logs** (`*-undo-*.jsonl`) — every applied change, with before/after
  SHA-256, the audio-payload digest, and the Serato-frame digest per file;
- the **result files** (`*-result-*.json`) — what each run actually did;
- the **completion reports and previews** (`*.md`) — the human narrative.

Inventories are also fully re-derivable: point `scripts/inventory_library.py`
at the same folder and you get the current equivalent.

The SHA-256 of each removed file is recorded so a specific version can still be
identified in Git history (`git log --all -- <path>`), which is not rewritten by
this change — the objects remain reachable there.

## Preventing recurrence

`.gitignore` now excludes nested `inventory.json` / `inventory.csv` /
`tracks.json` anywhere in the tree, not only at the repo root, so a future run
writing its inventory into a nested survey folder cannot be committed by
accident.

Git history is deliberately **not** rewritten here. That is a separate,
explicitly-authorized operation — it invalidates every existing clone and
in-flight branch, and this repository is worked by several concurrent sessions.
